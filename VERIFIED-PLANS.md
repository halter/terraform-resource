# Opt-in verified saved plans

This protocol is source-only; it does not authenticate approval, validate Terraform changes, publish evidence or establish no drift. Before enabling it, release and pin the **same reviewed resource image digest for every put/get**, verify the actual Concourse resource-type resolution, and require the capability marker and hashes below. An old resource ignores unknown parameters: flags alone are not a security gate. Pin an independently trusted validator/expectation and serialize *all* plan and apply jobs sharing each `<environment>-plan` workspace. Concurrent overwrites fail checks but can still prevent progress. No automated destructive cleanup on validation failure.

0. Before **any** plan put (and therefore before any possible log leak), run `/opt/resource/capabilities` from a task using the same pinned image digest. Require successful exit and exactly `slack-import-plan/v1` followed by a newline on stdout. Missing/mismatched capability blocks the plan. The marker is only an image-local capability check, not a substitute for verifying image provenance/digest or a signed attestation.
1. Strict plan put: `params: {env_name: tools, terraform_source: ..., plan_only: true, sensitive_plan: true}` and implicit `get_params: {verified_plan: true}`. No imperative `import_files`, delete-on-failure, destroy, plan-run, legacy/migrated/local backend, generated name or workspace creation is permitted. Declarative Terraform import blocks are part of the plan. The target workspace must already exist.
2. The strict put computes `terraform show -json` on its saved binary, checks the binary, and returns Concourse version fields `verified_protocol: slack-import-plan/v1`, `plan_checksum` and `plan_json_checksum`. The verified get rejects missing/wrong protocol or checksums and verifies both backend artifacts against that version. This avoids requiring repository/provider schemas in the get container. It outputs `plan.tfplan`, `plan.json`, `plan-metadata.json` as 0600 private build artifacts; do not print, upload or log plan files. Metadata contains `protocol`, `environment`, `terraform_version`, `binary_sha256`, `json_sha256`, `source_version`. The source version is a protocol capability label, **not** an image digest or proof of release provenance.
3. A separately trusted validator must verify capability, both hashes, exact workspace/app/approval/source identity, full raw Slack/collaborator observations and no-drift policy. Its task must emit the selected binary SHA-256 as lowercase 64-hex (optionally newline) to a private file. `load_var` with `format: trim` provides it as `expected_plan_checksum: ((.:import-plan-checksum))`. The resource accepts only the literal checksum, not a file path.
4. Apply put uses `params: {env_name: tools, terraform_source: ..., plan_run: true, verified_plan: true, expected_plan_checksum: ...}` and `get_params: {verified_apply_result: true}`. The resource downloads the saved plan and hashes it immediately before applying that same local file. Missing/malformed/mismatched checksum, direct replan, plan-only, destroy, imports, or cleanup-on-failure fails closed before apply. Verified apply returns no raw state outputs; its implicit get emits `apply-result.json` (0600) with `protocol`, `environment`, `applied_binary_sha256`, `source_version`. Validate this pipeline-local receipt against the approved plan; it is not an independently authenticated proof and cannot alone establish a successful import. If apply succeeds but subsequent state read/cleanup fails, no receipt is emitted: outcome is ambiguous and requires read-only reconciliation, not blind retry.

Strict modes discard Terraform stdout/stderr and return fixed errors, including on init/show/apply failure. They strip `TF_LOG*`, `TF_CLI_ARGS*`, `TF_WORKSPACE`, and `TF_REATTACH_PROVIDERS` from inherited and model-supplied environments before Terraform commands; workspace values set internally for read-only commands remain explicit. For troubleshooting do not expose raw output, which can contain manifest fields. Default behavior of all non-opt-in paths remains unchanged. The normal saved-plan workspace backend itself contains sensitive plan material and requires existing private state protection. This feature does not address PR plans built by other scripts: they too must suppress human Terraform output before adoption is enabled. These source tests use a synthetic CLI and no cloud/backend acceptance; validate the real pinned Concourse/registry image release and non-production behavior through an explicitly approved process.
